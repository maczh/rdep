- **口令存储从无盐 SHA-256 升级为 PBKDF2（真实凭据保护）**：审计发现 service 与 forwarder 的 `users` 表都存**裸 `sha256(password)`**——无盐（相同口令同哈希，可彩虹表）且无工作因子（SHA-256 极快，GPU 每秒数十亿次）；当初注释写了「仅用于开发期」却一直没修。新增 `password` 模块（两个 crate 各一份）：PBKDF2-HMAC-SHA256 + `getrandom` 16 字节盐，格式 `pbkdf2-sha256$<rounds>$<salt>$<hash>`（轮数自描述，可平滑调参），**常量时间比较**，畸形存储值一律拒绝。**向后兼容**：`verify` 同时接受旧裸 SHA-256，`Db::auth` 认证成功且 `needs_rehash` 时**就地透明升级**为 PBKDF2——部署升级后用户下次登录即生效，无需强制改密。**这一轮踩了三个坑，暴露了我对"KDF 代价"考虑不足**：①改完 16 个集成测试**全部失败**（panic 在 `.expect("connected")`），我第一反应是"KDF 阻塞 tokio worker"→ 加 `Db::auth_async` 用 `spawn_blocking` 派发 KDF（**这个改动本身是对的、也确实必要**，CPU 密集 KDF 跑在 async worker 上是真实 DoS 向量），但**并没有解决失败**；②实测才发现真正原因：**debug 构建下 PBKDF2 210k 轮要 3.36 秒**（release 仅 106ms），而 `Db::open` 要为默认账户算 KDF → **发生在监听之前**；测试 helper 又是固定 `sleep(500ms)` 就让客户端连，端口根本没监听，客户端首次连接被拒（它只在会话建立后才重试）。修法：新增 `wait_port_ready()` **实际探测端口**替换全部固定 sleep（固定 sleep 本身always脆弱），并把默认轮数降到 100k（release ≈50ms 仍无感，debug 减半），文档写明生产建议 `RDEP_PBKDF2_ROUNDS=600000`；③加了 `spawn_blocking` 后进程 **SIGABRT: memory allocation failed**——tokio 默认允许 512 阻塞线程，16 个测试服务各建 runtime 导致线程爆炸。修法：service/forwarder 的 `main.rs` 从 `#[tokio::main]` 改为**显式构建 runtime 并 `max_blocking_threads(16)`**（生产上同样是「认证洪泛时线程无界增长」的真实风险，改为可预期常数），测试 runtime 设 2。教训：**"单测全绿"曾让我误以为安全，实测构建模式差异 + 固定 sleep 才暴露问题**。最终：编译无警告、协议 5/5、service **17/17**（+5 口令模块 +3 认证迁移）、forwarder **9/9**、client 19/19、rdep 集成 **16/16**、FTP 端到端 2/2（合计 68 个测试）。

- 关键发现：russh-sftp 3.0.1 的**高版 `SftpSession` 没有 `setstat` 方法，但提供了等价的 `set_metadata(path, FileAttributes)`**（底层仍走 `SSH_FXP_SETSTAT`）。之前 Phase 8 以为「SftpSession 无 setstat 故 chmod 仅 rdep」是误判——应改走 `set_metadata`。
- 实现：`sftp.rs` 新增 `SftpCommand::Chmod{path,mode}` + `SftpClient::chmod` + 命令循环分派 `do_chmod`；`do_chmod` 调 `s.sftp.set_metadata(path, chmod_attrs(mode))`；`chmod_attrs(mode)` 只设 `permissions: Some(mode & 0o7777)`，其余字段 `None`（setstat 只应用显式字段，不会误清空 size/mtime）。
- `app.rs::do_chmod` 改为 `match backend`：Rdep→`client.chmod`、Sftp→`sftp.chmod`、Ftp→仍门控日志。i18n 把 `chmod requires the rdep protocol...` 改为 `chmod not supported over FTP; current site is {p}, skipped`（SFTP 已支持）。
- 测试：新增 `sftp::tests::chmod_attrs_only_permissions`（断言只设 permissions）；`chmod_gating_rdep_vs_ftp` 改名 `chmod_dispatch_rdep_sftp_vs_ftp`（Rdep/Sftp 不拦截、Ftp 拦截含 "FTP"）；`sftp_live.rs` 连通后追加 chmod 往返验证（#\[ignore\] 需本机 sshd）。
- **验证**：`cargo test --lib -p rdep-client` 50/50、`-p rdep-protocol` 5/5、`-p rdep-service` 22/22 全绿；`cargo clippy` 改动源文件（sftp.rs/app.rs/i18n.rs）0 warning；`sftp_live` 那条预存风格 warning 与本次无关。
- 文档：`docs/phase8-overview.md` + `docs/03-roadmap.md` 的 chmod 项改为「rdep + SFTP」；`MEMORY.md` 同步。
- **教训**：russh-sftp 3.x 改权限用 `SftpSession::set_metadata` 而非 `RawSftpSession::setstat`；别被「没有 setstat」误导而放弃 SFTP chmod。
